Adafruit GFX Bitmap Converter

Generate the horizontal, MSB-first byte arrays that display.drawBitmap() expects, for any display that uses the Adafruit_GFX library.

drawBitmap() signature

void drawBitmap(int16_t x, int16_t y,
                const uint8_t bitmap[], int16_t w, int16_t h,
                uint16_t color);
void drawBitmap(int16_t x, int16_t y,
                const uint8_t bitmap[], int16_t w, int16_t h,
                uint16_t color, uint16_t bg);

The array must be ceil(w / 8) × h bytes long. Each row starts on a new byte, so a 10-pixel wide icon uses 2 bytes per row.

Adafruit_SSD1306 display(128, 64, &Wire, -1);

// Paste the array generated above:
static const uint8_t PROGMEM bitmap[] = { 0xff, 0x80, /* ... */ };

void setup() {
  display.begin(SSD1306_SWITCHCAPVCC, 0x3C);
  display.clearDisplay();
  display.drawBitmap(0, 0, bitmap, 128, 64, SSD1306_WHITE);
  display.display();
}

void loop() {}

Color TFT displays

On ST7735, ST7789 and ILI9341, drawBitmap() paints the 1-bits in any 16-bit color you choose, which is perfect for icons. For full-color images use drawRGBBitmap() with RGB565 data – the RGB565 viewer decodes that format.

Frequently asked questions

What is the difference between drawBitmap and drawXBitmap?

drawBitmap() expects MSB-first bytes (this tool's Adafruit GFX output). drawXBitmap() expects XBM, LSB-first – choose the XBM output for it.

Do I need PROGMEM?

On AVR boards yes, otherwise the array is copied into scarce RAM. On ESP32 and ARM const arrays stay in flash anyway, and PROGMEM is harmless.
